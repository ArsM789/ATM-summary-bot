# ATM Morning Assistant

Персональный Telegram-бот: утренняя (и не только) сводка с реальной погодой, советами по одежде и количеством уроков.

**Статус разработки:** этапы 1–2 готовы (архитектура, ядро, главное меню, кнопка «Сводка»).
Настройки (этап 3), планировщик (этап 4) и Inline Mode (этап 5) — следующие.

## Что работает сейчас

- `/start`, главное меню (🌤 Сводка · ⚙️ Настройки · 📅 Расписание).
- **🌤 Сводка** — реальная погода из Open-Meteo, день недели и дата в часовом поясе пользователя, рекомендации по одежде, количество уроков, живые меняющиеся формулировки. Время суток (утро / день / вечер / ночь) меняет содержание: вечером бот рассказывает про завтра.
- Кнопка **🔄 Обновить** под сводкой.
- **⚙️ Настройки** и **📅 Расписание** пока только *показывают* реальные сохранённые данные (изменение — этапы 3 и 4).
- Если Open-Meteo недоступен, бот честно пишет об этом и присылает только то, что знает точно (дата, уроки) — погоду не выдумывает.
- SQLite создаётся автоматически; новый пользователь получает город/пояс из `.env`, уроки 7-6-6-7-7-0-0 и одно уведомление на 07:00 (оно начнёт срабатывать после этапа 4).

## Установка на macOS

```bash
# 1. Python 3.12 (если нет): https://brew.sh, затем
brew install python@3.12

# 2. Виртуальное окружение и зависимости
cd ATM_Morning_Assistant
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# 3. Конфигурация
cp .env.example .env
open -e .env        # впишите BOT_TOKEN

# 4. Запуск
python main.py
```

Остановка — `Ctrl+C`. Бот должен работать постоянно: когда процесс остановлен или Mac спит, ответов и автосводок не будет.

## Создание бота в BotFather

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите отображаемое имя (например, `ATM Morning Assistant`) и username — он должен заканчиваться на `bot`.
3. BotFather пришлёт токен вида `123456789:AAH...`. Вставьте его в `.env` после `BOT_TOKEN=` (без кавычек и пробелов). Токен никому не показывайте; если он утёк — `/revoke` в BotFather.
4. Команды меню бот регистрирует сам при запуске.
5. *Для этапа 5 (Inline Mode):* `/setinline` → выберите бота → введите подсказку, например `Какая завтра погода?`. Без этого шага бот не будет отвечать на `@username …` в других чатах.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют форматирование, разбор времени и поясов, парсер ответа погоды (на синтетической фикстуре в формате Open-Meteo), правила одежды (включая перебор сотен сочетаний температуры/ветра/осадков на противоречия), генератор сводок (будни, выходные, вечер, пятница→суббота, недоступная погода, экранирование HTML) и схему SQLite.
Сеть, Telegram и aiosqlite эти тесты не затрагивают — их нужно проверить запуском.

## Чек-лист проверки этапа 2

1. `python main.py` — в логе «Бот запущен: @ваш_бот».
2. `/start` — приветствие и меню из трёх кнопок.
3. 🌤 Сводка — приходит сообщение с реальной погодой Казани; нажмите 🔄 Обновить — текст обновится другими словами.
4. ⚙️ Настройки / 📅 Расписание — показываются сохранённые данные.
5. Отключите Wi-Fi и нажмите «Сводка» — бот сообщит, что погоду получить не удалось, и не выдумает её.
6. Перезапустите бота — данные в `data/atm_morning.db` сохраняются.
7. Логи: `logs/bot.log`.

## Технические решения

- **APScheduler 3.11.x**, а не 4.x: ветка 4.x до сих пор в статусе alpha и не рекомендуется для продакшена.
- **aiogram ≥ 3.28.2**, один HTTP-клиент `aiohttp` (он и так зависимость aiogram), **aiosqlite** для асинхронной SQLite.
- **Погода:** Open-Meteo (ключ не нужен). Запрашиваются текущие данные, почасовой и дневной прогноз на 3 суток прямо в часовом поясе пользователя. Кэш по умолчанию 10 минут, тайм-аут 10 с, до 2 повторов с нарастающей паузой, не более 4 одновременных запросов.
- **Одежда:** не таблица, а правила — ощущаемая температура за период, когда пользователь на улице (утром — до ~17:00, вечером — завтрашний день), ветер и порывы, тип и вероятность осадков, гололёд, гроза, перепад температур, солнце. После правил идёт проверка на противоречия.
- **Кнопки:** Bot API 9.4 добавил цвет inline-кнопок (`primary` — синий, `success` — зелёный, `danger` — красный) и `icon_custom_emoji_id`. Цвет виден только в свежих клиентах Telegram, старые показывают обычную кнопку. Бот использует `primary` для «Обновить»; остальные цвета пригодятся в этапах 3–4 (например, красный для удаления).
- **Premium Custom Emoji:** в сообщениях работают через `<tg-emoji emoji-id="…">`, но показываются только если у владельца бота есть Telegram Premium (либо бот купил доп. юзернеймы на Fragment). Настоящих id в код я намеренно не вписывал: по умолчанию используются обычные эмодзи, а свои id можно задать в `CUSTOM_EMOJI_IDS` (формат в `.env.example`).
